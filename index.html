SynapNet-Edge — Edge Model Compression, Measured Honestly

An 8.7M-parameter hybrid SSM-attention-memory model with component-aware quantization and a 3.3K-parameter learned memory-eviction policy (71% of critical context retained under 90% memory pressure, versus 0% for FIFO/LRU). On a Raspberry Pi 4, bit-packed size fell from 16.6 MB to 10.2 MB (INT8) and 8.4 MB (INT4), within about 2 points of FP16 on retrieval up to 4K tokens, but latency rose 2–18% and RAM stayed near 350 MB because the Cortex-A72 has no native low-bit kernels. A matched-control study (11 variants, 3 seeds, paired bootstrap CIs) showed an earlier QAT gain was a fine-tuning effect, not a quantization effect.

PyTorch QAT SSM / Mamba Raspberry Pi 4 Edge AI

An edge-first quantized VLM pipeline (SmolVLM) that detects your hardware, picks a model size that fits, and constrains decoding so the JSON output is valid by construction. 04 — Learnings

What the benchmarks taught me

Edge inference · SynapNet-Edge

Smaller is not automatically faster

INT8 and INT4 models were up to 2x smaller on disk but 2–18% slower on a Raspberry Pi 4 with RAM unchanged. The weights are dequantized to float on every pass, the Cortex-A72 has no INT8 dot-product path, and the runtime and activations dwarf 8–17 MB of weights. Next: qnnpack or ONNX Runtime INT8 kernels, a quantized positional table, and a Pi 5 or NPU target.

Experiment design · SynapNet-Edge

Control for the fine-tune, not just the quantizer

A quantization-aware-training gain over FP16 vanished once FP16 got the same 200 fine-tuning steps; it was slightly ahead at 4K context. The fix was a matched control, 11 variants, 3 seeds and paired bootstrap confidence intervals instead of single-run comparisons.

Measurement hygiene · SynapNet-Edge · VisionFlow

Audit the benchmark before you trust it

I caught three of my own errors before reporting: a benchmark run on the wrong architecture, a 3 MB positional table missing from the size estimate, and a 48-question eval too noisy to rank variants. In VisionFlow, two tiers measured in one process reported memory figures 0.01% apart because the second read the first one's allocations, so every configuration now runs in a fresh subprocess.

Product scope · Hearth

Write the limits next to the results

Each of my recent READMEs has an honest-limits section: Hearth is single-user and untested against real Alexa+, VisionFlow reports 21 fields over three images, and a TensorRT row that fell back to CPU is labelled as such. Claims that survive a skeptical reader are the only ones worth putting on a resume.
